JavaScript & the DOM

JavaScript runs in the browser. It can read and change your page through an object model called the DOM (Document Object Model): the browser turns your HTML into a tree of elements you can select and mutate. You add a <script> and go.

Select an element

const button = document.querySelector('#save')        // first match
const items  = document.querySelectorAll('.item')     // ALL matches (a list)

querySelector takes any CSS selector — #id, .class, [data-x]. This is why good class/attribute names matter in HTML.

Change it

CodeEffect
el.textContent = 'Hi'set visible text (safe)
el.classList.toggle('on')add/remove a class
el.setAttribute('aria-pressed','true')set an attribute
el.hidden = truehide it

Prefer textContent over innerHTML for user input. innerHTML parses text as HTML — feed it a message containing <script> and you have an XSS hole. The app's chat view uses textContent for exactly this reason.

React to events

button.addEventListener('click', () => {
  console.log('clicked')
})

The callback receives an event object: event.target is the element that was clicked.

Event delegation — the big idea

If you have 42 table rows, do you attach 42 listeners? No. Attach one to a parent and check what was hit. It survives rows being added or removed, and uses less memory. This is how the entire app is wired (src/main.js has one click listener for every widget). 

list.addEventListener('click', (event) => {
  const item = event.target.closest('[data-item]')
  if (!item) return                 // the click missed every item
  item.classList.toggle('done')
})

State + render

Most UI bugs are state bugs: the variable and the screen disagree. The cure is a rhythm — keep data in a variable, and write one function that paints the screen from it. Change the data, call the function. The app's table does exactly this (state → render()). 

let done = false

function render() {
  box.classList.toggle('bg-green-500', done)
  box.textContent = done ? 'Done' : 'Todo'
}

button.addEventListener('click', () => {
  done = !done   // 1. change state
  render()       // 2. paint it
})

Live example — toggling a list

Click items to toggle them. One listener, many items.

// (from this page's own script)
list.addEventListener('click', (event) => {
  const item = event.target.closest('[data-item]')
  if (!item) return
  const on = item.classList.toggle('line-through')
  item.classList.toggle('opacity-60', on)
  item.setAttribute('aria-pressed', String(on))
})

How the app swaps views

Open src/main.js and read the top. It keeps a registry mapping an id to an HTML string, and switchView(id) sets #view to that string, then runs the view's optional init(). That is the same job React/Vue do — just without the framework.
