Tailwind basics

In lesson 1 you met the class attribute — a label you stick on an element. Tailwind turns those labels into styling. Instead of naming your own classes and writing CSS in a separate file, you build the look out of many tiny, pre-made classes.

One class = one small CSS rule

CSS is the language of visual style: colour, size, spacing, borders, layout. Each CSS rule has a property and a value (color: white;). Tailwind ships thousands of ready-made classes, each one setting a single property. You stack them in the class attribute, separated by spaces: 

<button class="rounded-lg bg-brand-600 px-4 py-2 text-sm font-medium text-white">
  Save
</button>

The naming is a compact shorthand: p = padding, x = horizontal, y = vertical, bg = background, text = text colour or size. Once you know the pattern, you can guess most classes.

Why not just write CSS?

You can — and sometimes you should (lesson 07). The trade-off is naming and globals. Plain CSS needs a name for every pattern and grows into a file you're afraid to delete from. Tailwind keeps the styling next to the markup and only ships the classes you actually use.

Plain CSS

.btn {
  background: #4f46e5;
  color: white;
  padding: 0.5rem 1rem;
  border-radius: 0.5rem;
  font-size: 0.875rem;
}

Tailwind

class="bg-brand-600 text-white
py-2 px-4 rounded-lg
text-sm"

The scales

Three number systems cover most of what you'll write:

  • Spacing — p-1 = 0.25rem = 4px. So p-4 = 16px, p-8 = 32px. Every gap, margin and padding uses this one scale.
  • Colour — a family plus a shade: brand-600, gray-500, red-700. Shade 50 is lightest, 950 darkest. Add /opacity: bg-black/50 is 50% black.
  • Type — text-xs … text-4xl for size (they set both font-size and line-height), font-medium/font-semibold/font-bold for weight.

Prefixes = variants

A prefix makes a class apply only in a certain situation. The rest of the class is unchanged. Hover the examples and try them in dark mode:

focus-visible:when reached by keyboard (a focus ring)

dark:when dark mode is on

How Tailwind actually works

The build tool scans your files for class names and writes CSS for only the ones it finds. A class you never type is never shipped. The flip side: a class name must appear as complete text somewhere — you cannot build it by joining strings at runtime, or Tailwind won't see it. This is the single most common Tailwind beginner bug. 

// ❌ Tailwind never sees "bg-red-500" as a whole word
el.className = "bg-" + color + "-500"

// ✅ write full class strings
el.className = isError ? "bg-red-500" : "bg-green-500"
