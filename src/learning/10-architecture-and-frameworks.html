Architecture & frameworks

An application is a page minus the reload. Its core idea is simple and old: keep the chrome fixed, swap the content, and let a router decide which content shows for which URL. The pattern library you have been reading is exactly that, built in about 20 lines.

The mantra is UI = f(state): the screen is a function of your data. When a bug shows something stale, the fix is almost always "repaint from state".

Components: stop copy-pasting

When the same markup appears three times, make a function that takes data and returns an element. That function is a component. Its input is called props. 

function userCard(user) {
  const el = document.createElement('div')
  el.className = 'rounded-xl border p-4'
  const h = document.createElement('h3')
  h.textContent = user.name
  const p = document.createElement('p')
  p.textContent = user.role
  el.append(h, p)
  return el
}

users.forEach((u) => list.append(userCard(u)))

Notice textContent again: a component that feeds user data into innerHTML is an XSS bug waiting to happen.

Routing: make the URL honest

The app swaps views in memory, so the URL never changes — delightful for a demo, wrong for a real app (no shareable links, broken back button). The fix is two lines and one listener: 

function go(id) {
  location.hash = '#/' + id    // updates the URL
}

window.addEventListener('hashchange', () => {
  switchView(location.hash.replace('#/', '') || 'landing')
})

This is exercise #1 in the repo README — do it and the SPA suddenly has real links and a working back button.

Where frameworks fit

React and Vue do not invent new ideas. They automate the parts you just did by hand — and they're worth it once state gets complicated.

You wroteFramework equivalent
switchView()React Router / Vue Router

Learn one, not all. React transfers most directly; Vue reads a lot like this markup. Everything you learned here — events, state, a11y, tokens — carries over unchanged.

The rest of the job

  • TypeScript — JavaScript with types; catches whole classes of bugs before you run anything.
  • Testing — unit tests (Vitest) and an end-to-end browser test (Playwright) for the one flow that must never break.
  • Tooling & CI — a formatter and linter, plus a pipeline that builds on every push (this repo deploys via GitHub Actions).
  • Performance — measure, don't guess: the browser's Lighthouse panel and DevTools performance tab.
  • Accessibility — lesson 9, practiced on every real project, not once.

The honest ceiling

This curriculum teaches the pattern track: how real UI is structured and why. Reaching "build any modern UI" also needs hands-on CSS depth (you: break and rebuild layouts until flexbox is instinct) and real JavaScript practice (build small apps with data). No single repo gets you there — reps do.
