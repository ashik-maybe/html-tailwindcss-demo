Animations & transitions

Without motion, a hover state snaps. One class — transition — tells the browser to interpolate between the before and after values instead.

Transitions: smooth a state change

Put transition on the element, then use any state prefix as usual. Tune it with duration-*, ease-*, and delay-*.

Live example — hover both

Prefer a specific transition (transition-colors, transition-transform) over transition-all — it's cheaper and avoids animating things you didn't mean to.

group-hover: parent drives the child

When the hover is on a parent but you want to style a child, mark the parent group and prefix the child with group-hover:. This is how image-zoom product cards work. 

<a class="group block overflow-hidden">
  <img class="transition duration-300 group-hover:scale-110" src="…" />
</a>

Keyframe animations

Animations run on their own, looping or playing once. Tailwind ships four: animate-spin, animate-ping, animate-pulse, animate-bounce.

For your own, define it in CSS (v4 style) and it becomes a utility. This is where the repo's src/style.css would hold it: 

@theme {
  --animate-wiggle: wiggle 0.4s ease-in-out infinite;
}

@keyframes wiggle {
  0%, 100% { transform: rotate(-3deg); }
  50%      { transform: rotate(3deg); }
}

/* now `animate-wiggle` exists as a utility */

Respect reduced motion

Some people get dizzy from motion, and can set an OS preference. Honour it — two ways:

  • Per element: add motion-reduce:animate-none or motion-reduce:transition-none.
  • Globally: one @media (prefers-reduced-motion: reduce) rule that collapses every duration. The app does exactly this in src/style.css so you can't forget.
