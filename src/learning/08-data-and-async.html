Data & async

JavaScript runs one thing at a time. If it sat and waited for the network, the page would freeze. So requests are asynchronous: you start them and attach what to do when they finish. The tool for this is async/await.

A Promise is "a value, later"

The browser's fetch() returns a Promise: an object representing a value that isn't ready yet. It either resolves (works) or rejects (fails). await pauses just this function until the Promise settles, without freezing the page. 

async function loadUsers() {
  try {
    const res = await fetch('/api/users')
    if (!res.ok) throw new Error('Request failed: ' + res.status)
    return await res.json()
  } catch (error) {
    // network down, bad status, bad JSON — all end up here
    throw error
  }
}

The four states of a request

StateWhat the user should see
LoadingA skeleton or spinner — never a blank screen
SuccessThe data
Empty"Nothing here yet" + a next step
ErrorA plain message + a Retry button

The app's Loading & States view is the visual half of this. A single render(status) function keeps the screen honest with the state.

Race conditions & cancellation

If a user fires two requests and the first is slower, a stale response can overwrite a fresh one. Two defences:

  • AbortController — cancel the in-flight request when a new one starts or the view closes.
  • A token/guard — check the request is still the latest before painting its result.
let controller

async function load() {
  controller?.abort()          // cancel the previous request
  controller = new AbortController()
  const mine = controller

  const data = await fetchUsers({ signal: controller.signal })
  if (mine !== controller) return   // a newer request started — drop this result
  render(data)
}
