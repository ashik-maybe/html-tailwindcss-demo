Design tokens & CSS

A design token is a named value you reuse everywhere — a brand colour, a font, a spacing step. In Tailwind v4 tokens are declared in CSS with @theme, and each one automatically becomes utilities.

CSS custom properties, first

Everything here rests on a plain CSS feature. You define a variable with a double dash and read it with var(): 

:root { --color-brand: #6366f1; }

.button { background: var(--color-brand); }

You can also set them inline, which is a neat way to feed one value into many rules. This bar's height comes from a custom property:

Live example

<div style="--h: 80%" class="h-[var(--h)] bg-brand-500"></div>

@theme turns tokens into utilities

This is the v4 config — a block in your CSS. Each entry becomes a custom property and a set of classes. The app's brand colour: 

@theme {
  --color-brand-500: oklch(0.585 0.158 277.117);
  --font-sans: "Inter", ui-sans-serif, system-ui, sans-serif;
}

/* --color-brand-500  →  bg-brand-500, text-brand-500, border-brand-500 … */
/* --font-sans        →  font-sans  (and the default body font)          */

Because the app defines --color-brand-* and --font-sans once, every view and every lesson page shares them. That is the whole point of tokens: change one line, update the product.

Escape hatch: arbitrary values

When you need a one-off value that isn't in the scale, put it in square brackets. It compiles to exactly that CSS:

ClassCSS
bg-[#0ea5e9]background-color: #0ea5e9
w-[37px]width: 37px
text-[13px]font-size: 13px
grid-cols-[200px_1fr]grid-template-columns: 200px 1fr
bg-[#0ea5e9] text-[13px] colour

Use these sparingly. If you reach for the same arbitrary value three times, promote it to a token in @theme instead.

Wiring a variant: dark mode

dark: is a variant. Tailwind's default watches the OS; the app redefines it to watch a .dark class so a button can flip it: 

@custom-variant dark (&:where(.dark, .dark *));

/* now dark:bg-gray-900 applies when an ancestor has class="dark" */

When to write plain CSS

Not everything is a utility. Some things have no class equivalent — like a pseudo-element. That is the honest place to drop into CSS, inside @layer base: 

@layer base {
  dialog::backdrop {
    background-color: rgb(0 0 0 / 0.5);
  }
}

You can also mint your own utility with @utility: 

@utility card {
  border-radius: 1rem;
  border: 1px solid var(--color-gray-200);
  padding: 1.5rem;
}

/* now `card` is a real Tailwind utility, variant-aware: dark:card, hover:card */

Modern CSS also nests natively, which keeps plain sections readable: 

.field {
  border: 1px solid gray;

  &:focus { border-color: var(--color-brand-500); }
  &.invalid { border-color: red; }
}
