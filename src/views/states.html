UI states

Loading, empty, error and toast — design these BEFORE the happy path.

Loading — skeletons

Skeletons mirror the REAL layout (same heights/widths), so content swaps in without the page jumping — no cumulative layout shift. Spinner-only loading is slower to read: users can't preview structure.

Empty — nothing here yet

An empty state is a pitch, not an apology: say what goes here and give ONE obvious action. Never show a blank area with no explanation.

Error — failed, with a way out

Three ingredients: what happened (plain words), why it matters, and the retry/escape action. Red text alone tells a screen reader user nothing — pair color with an icon, a heading and role="alert". (a11y)

Toast — transient confirmation

The toast host lives in the SHELL (index.html) so messages survive view switches. aria-live="polite" on the host announces new toasts without interrupting the current utterance. Fires here via showToast() in main.js — the same helper Shop uses after "Add".
